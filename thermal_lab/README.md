# Thermal Lab

All workstream source is in this package. Shared fleet/routing engines and requirements are unchanged.

The reference model retains the exact existing fleet-card outputs referenced by `docs/research-notes.md`. The browser opens the optimistic Case B profile from `page/scenarios.mjs`, using cited proxies and assumptions from `page/sources.mjs`. Cases A (4B prompters), B (50M agent developers), and C (400M knowledge workers) are available. No new measured QC efficiency data is claimed.

## Reproduce source inputs and hosted evidence

```sh
node thermal_lab/export-reference.mjs
uv sync --locked --group dev
uv run python -m thermal_lab.snapshot
```

`page/fleet-reference.mjs` is generated by importing the existing `web/src/model/brief.ts` and `fleet.ts`. It records the research-notes content hash. It includes baseline, brief-lever and speculative-decoding values for all three cases, without duplicating those models. Reference power is direct liquid/cold PUE 1.07; selectable cooling uses the same source table.

The model timeline is 2030–2040 inclusive. The source hardware remains the fixed 2035 catalog. All trend rates default to zero; nonzero trends are explicit hypothetical scenarios and are not derived from Moore’s law or Neven’s law.

## Amounts and spending

Research-note reference values round to:

- A: 981 MW / $27.5B in baseline racks; no beneficial brief levers; 456 MW / $12.8B with the speculative-decoding assumption.
- B: 704 MW / $19.8B → 306 MW / $8.6B with the brief levers; 196 MW / $5.5B with speculative decoding.
- C: 734 MW / $20.6B → 339 MW / $9.5B with all brief levers; 218 MW / $6.1B with speculative decoding.

Rack equivalents retain source precision. The site schematic rounds physical racks up. Recommended profiles supply every active numeric input: costs use cited proxies and explicit allowances; thermal resistance, dispatch latency, prefill/support allowances and extra QC throughput remain labelled assumptions. The spending view separates paid capital, annual running costs and cumulative spending. Retiring a purchased GPU rack never refunds its cost.

The initial routing fleet is chosen by the Recommendation goal: lowest five-year modeled spend among four starting-fleet candidates, or the smallest feasible initial fleet for gradual one-per-year rollout. All recommendations use the source's two-accepted-token speculative-decoding assumption. Routing units are assumed to cover 25% of 2030 assignments each. Coverage saturates at 100%; additional hardware does not gain an automatic benefit. Scientific QPUs have separate schedules and parameters.

## QC rollout and workload accounting

`model.mjs` now interpolates the baseline-to-source-policy opportunity according to installed QC routing coverage, then applies an explicit assumed extra throughput on covered work. This is a proposed architecture, not execution of a quantum algorithm. The optimized classical comparator keeps the full source-policy improvement, allowing the assumed extra QC advantage to be tested against it. Set the extra gain to zero to remove that assumption.

Router power and acquisition cost scale with unit count. Avoided capacity is not a refund: purchased GPU racks remain in cumulative capital even when retired. Optional scientific QPUs are independent and only remove the eligible tool workload they can execute. Unused systems add power without a benefit.

GPU execution share, quantum-tool execution share and unserved workload sum to 100% using the same baseline GPU-work-equivalent denominator. QC assignment coverage is a separate planning metric, never added to executed work. Capacity coverage is not measured utilization, proof of output quality or deadline validation. Year-labelled cards use the global selected year; chart points and annual-table buttons update it. The cards also show the final 2040 quantum count.

## Case presets and input completeness

`page/scenarios.mjs` defines the active reference/conservative/moderate/optimistic routing scenarios. Choosing a case or preset reloads a full case-specific profile; references use source policies without routing QPUs, and QC scenarios assume 0/5/10% extra throughput. All recommendations enable the existing two-accepted-token speculative-decoding assumption. The recommendation defaults to Annual deployment: it chooses a passing first-year assignment adoption share and initial routing fleet, then migrates assignments through 2040 within installed capacity. Lowest five-year cost is an alternative four-candidate search that can deploy everything up front. Neither search is a global hardware optimizer.

The UI now updates numeric controls on input and selects on change using stable delegated handlers. Cleared active required values are not converted to zero. A missing-input banner names the fields and hides calculated output until restored. Optional scientific job/price fields become required when that pool is enabled. The filled thermal resistance (0.009 K/W), temperature limit (85°C), routing decision latency (50 ms), 5% prefill power allowance and 2 MW support allowance are explicitly chosen scenario assumptions, not new measurements or a complete prefill/memory model.


## Annual deployment view

The default recommendation is now Annual deployment, not minimum five-year cost. It searches the smallest initial router fleet and first-year assignment adoption share that pass the entered screens while leaving assignments to migrate in later years. Adoption interpolates to 100% by 2040, capped by installed routing hardware. This schedule is an explicit commissioning assumption, not automatic quantum-chip progress. Power and annual running costs decrease under these default assumptions; cumulative spending continues to accumulate. Lowest-cost upfront deployment remains an alternative.

Routing and scientific pools have independent enable/disable switches in the Quantum roles cards. Routing can also be toggled in the main rollout controls. Enabling scientific QPUs loads an existing feasible chemistry profile from the saved engine metadata and explicit 10% additional scientific-work / 100% eligibility assumptions; these assumptions remain editable. Scientific availability remains anchored to 2035.
